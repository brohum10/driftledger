# DriftLedger

**Know when your model's input data changed before trusting the next release.**

[![Tests](https://github.com/brohum10/driftledger/actions/workflows/tests.yml/badge.svg)](https://github.com/brohum10/driftledger/actions/workflows/tests.yml) · [Explore the live example report](https://brohum10.github.io/driftledger/)

DriftLedger compares two CSV snapshots and produces a reviewable dataset release report. It checks numeric and categorical feature distributions, missing values, column changes, and cohorts. The output includes explicit thresholds, sample sizes, source hashes, a machine-readable JSON file, and a self-contained HTML report. Python 3.12+; **no pip dependencies, API keys, or cloud account required**.

## See the problem in one minute

The bundled data is **synthetic support-routing data**, generated by [a fixed-seed script](example/generate.py). The candidate snapshot simulates a rollout that changes channel mix, increases missing description lengths, and lengthens the EU queue. It contains no customer data.

| Signal | Reference → candidate | Configured alert threshold | Observation |
| --- | ---: | ---: | --- |
| EU queue-time distribution | TV **0.771263** | 0.20 | Alert |
| US queue-time distribution | TV **0.067700** | 0.20 | Within threshold |
| Overall channel mix | JS **0.043130** bits | 0.04 | Alert |
| Missing description length | **+12.33 percentage points** overall | 10 points | Alert |

The global queue-time score is **0.266667**, but the cohort view makes the change more useful: EU is the source of the shift, while US stays below the threshold. This is a synthetic screening scenario, not evidence of a real production incident or model quality loss. [The full JSON report](docs/report.json) records all **7 threshold crossings** across the global and cohort views, plus sample counts and exact input hashes.

## Run it

Clone or download this repository, then run from its root:

```sh
python -m unittest discover -s tests -v
python -m driftledger example/reference.csv example/current.csv \
  --config example/config.json --out local-report
```

Open `local-report/index.html`. The same observations are in `local-report/report.json`. To use it as a release gate, add `--fail-on-alert` (exit code **2** when an alert appears). Add `--fail-on-review` to also fail for cohorts or features that lack enough data. Invalid input exits **1**; a successful run without a triggered gate exits **0**. Output directories must be new, so prior evidence is never overwritten.

Regenerate the example data and report from source:

```sh
python example/generate.py
python -m driftledger example/reference.csv example/current.csv \
  --config example/config.json --out regenerated-report
```

The report timestamp will differ, but the source hashes, analysis ID, scores, and alerts should match the published example. CSV files are limited to 25 MB and 200,000 rows each. Empty cells mean missing; nonempty numeric values must be finite. The explicit config declares feature types, cohort column, minimum sample sizes, and thresholds; [see the sample config](example/config.json).

## How the comparison works

```text
Reference CSV ──validated + SHA-256──┐
                                     ├── schema and missingness checks
Candidate CSV ──validated + SHA-256──┤
                                     ├── global feature comparison
Explicit JSON config ────────────────┤
                                     └── eligible cohort comparisons
                                             │
                                HTML + JSON evidence, CI exit status
```

- **Numeric:** derive up to four quintile cut points from the **reference only**, plus reference minimum and maximum. Put both snapshots in those fixed bins, including separate below-minimum and above-maximum buckets. Report total variation distance: `½ × sum(abs(pᵢ − qᵢ))`, from 0 (identical bin proportions) to 1 (disjoint bins). Using the reference only avoids moving the yardstick after seeing the candidate.
- **Categorical:** compare observed nonmissing category frequencies using Jensen–Shannon divergence in bits, from 0 to 1. The report includes category counts and the number of new categories, without dumping category values.
- **Missingness and schema:** check absolute missing-rate changes separately. Added or removed columns and unavailable configured features are explicit alerts. Missing cohort labels and new or vanished cohorts are also surfaced.
- **Cohorts:** compare each shared cohort only when both snapshots meet `min_segment_rows`. Smaller shared cohorts are marked **needs review**; they are never described as passing. The same reference-only bin rule applies within each cohort.

Thresholds are **policy choices**, not universal statistical cutoffs. A crossing prompts investigation; it does not prove a broken pipeline, a fair or unfair model, or a performance regression. Multiple cohorts and features can produce multiple alerts from one underlying change.

## Tests and measured run

The **12 tests** cover exact metric examples, constant numeric baselines, finite-value validation, schema changes, sparse and missing cohorts, HTML escaping, CLI exit codes, and a case where large cohort shifts cancel out globally. GitHub Actions tests Python 3.12 and 3.14 and regenerates the synthetic example.

The included [benchmark](benchmark.py) generates **25,000 rows per snapshot** and measures CSV parsing, validation, hashing, and comparison for three runs. On this local Apple Silicon machine with Python 3.14.2, the run durations were **925.30, 888.48, and 868.89 ms** (median **888.48 ms**); Python `tracemalloc` peaks were about **29.3 MB**. [Raw results and scope](benchmark-results.json) are committed. Data generation and report serialization are excluded. This is a local synthetic measurement, not a throughput guarantee or a comparison against other tools.

```sh
python benchmark.py --rows 25000 --runs 3 --output my-benchmark.json
```

## Boundaries

- Distribution drift is **not** model performance drift. Labels, predictions, delayed outcomes, calibration, and fairness checks belong in separate evaluation.
- Numeric histograms can miss shifts that stay inside the same reference bins; categorical JS can be noisy for sparse or high-cardinality features. Minimum sample sizes reduce but do not remove that risk.
- Reports omit raw rows but can reveal schema names, cohort names, aggregate values, and hashes. Review before publishing a report built from private data.
- One categorical cohort column and CSV inputs only. There is no streaming service, automatic threshold tuning, authentication, or production monitoring claim.

Google's [production ML monitoring guidance](https://developers.google.com/machine-learning/crash-course/production-ml-systems/monitoring) discusses data-distribution changes as one signal to watch. DriftLedger is an independent educational implementation. Developed with AI assistance; the data, thresholds, and benchmark are disclosed so results can be checked rather than taken on trust.
